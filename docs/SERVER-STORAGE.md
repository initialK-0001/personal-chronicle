# 試作のサーバー保存

## 現在の公開・下書き仕様（2026-11-15）

この節が現在の実装です。以下に残る「公開機能未実装」「公開見本のみ」「全APIが管理者専用」という記録は、今回の変更前の履歴です。

- `draft` は非公開の編集中内容、`posts` は最後に確定した内容として独立保持。自動保存で公開版を変更しません。
- エディタの「公開」「公開内容を更新」でのみ公開版を確定。「非公開にする」は一覧と記事ページから操作でき、本文・日時・編集中の下書きを削除せず保持します。再公開でもIDと初回日時を維持します。
- 従来の保存済み投稿は公開状態未指定のため非公開扱い。自動移行・自動公開しません。公開画面の見本表示は終了し、見本は管理画面に残します。
- `/api/public/posts` は `visibility=public` の確定内容を許可項目だけに限定して返します。下書き、管理情報、未承認コメントは含みません。検索・テーマ・作品集・記事ページはこのデータだけを使います。
- `/api/public/images/:hash` は現在の公開版による参照を毎回確認します。下書きだけの画像、非公開化後に他の公開投稿からも参照されない画像は404。取得済みデータを第三者の端末から回収する機能ではありません。
- 公開APIと公開画像は `Cache-Control: no-store`。管理API・画像原本は管理者認証が必要です。公開側は読み取り専用で変更操作は拒否します。
- R2の同一stateスナップショットを条件付き更新し、本文の公開状態と画像配信の可否を一致させます。`public-owner.json` は公開元の管理領域を指すサーバー内部情報で、公開レスポンスに含めません。復元時には管理領域を戻した後、この参照も復元するか管理者が明示的に再公開します。
- 保存先は引き続き試作R2であり、本番用の独立保存・外部自動バックアップ・画像EXIF除去・SSR/SEO・一般コメント受付は未完成。下書きの同時保持は従来どおり1件です。
- Sites自体は本人専用のまま。サイトを誰でも閲覧できる状態への変更、WordPress変更、DNS切替は実施していません。

## 配信構成

Sitesの既存本人専用アクセスを維持。Worker APIは全経路でプラットフォームが付ける `oai-authenticated-user-id` を要求。取得・画像配信も利用者ごとの領域に限定。外部公開APIはない。独立ホストへ移す場合はこのヘッダーをブラウザーから信頼してはいけない。認証ゲートが外部ヘッダーを除去して検証済みIDを渡すことが必須。

`r2: "BUCKET"` を宣言。今回は小規模な試作のため、投稿・下書きのスナップショットをJSONファイルとして画像と同じ非公開オブジェクト保管領域に置く。本番の検索・履歴・コメント用SQL設計は変更しない。JSONは1MiB、1画像は8MiBに制限。画像の形式はバイト先頭を検証するが、本番向けの画像再エンコード・EXIF除去は未実装。

利用者IDのSHA-256で保管先を分離。画像は内容のSHA-256で重複を抑える。取得URLだけを知っていても他利用者は読めない。状態の保存はR2のETag条件付きputで行い、古い版からの更新を409で拒否。初回生成もIf-None-Match条件で競合を拒否。競合時は自動的に上書きせず、入力の書き出しと再読み込みを案内する。

POSTは同一Originと専用ヘッダーを要求。入力型・サイズ・画像参照・URLスキームを検証し、サーバー側で日時を決定。匿名・不正Origin・所有しない画像参照は拒否。本文のHTMLはクライアント側で文字としてエスケープ。公開済み見本への変更と下書きは別に保持する。

## 移行と復旧

画面下部の「投稿をバックアップ」で、全投稿・下書き・参照画像を含むJSONを取得できる。バイナリはこの持ち出しファイルに限ってdata URLとして同梱。ソースリポジトリには保存しない。元の画像が取得できなければ不完全な出力を成功として扱わない。

旧ブラウザー保存領域は自動転送・削除しない。「旧試作データを書き出す」で読み出せる。サーバーへの取り込み・復元画面は未実装であり、現時点の書出を完成した復旧機能と呼ばない。

Xserverの契約・接続先・認証方式は未確認。独立した本番保存先の確保、定期外部バックアップ、復元試験が完了するまで、この試作を本番保管の唯一の場所として扱わない。削除APIはなく、投稿内で外した画像も自動消去しない。孤立画像の整理・容量総量制限・リクエスト頻度制限は本番前の課題。

## 閲覧画面と管理画面の分離（2026-11-15）
- `/` は閲覧用画面。緑の表題部は画面幅いっぱいに表示。「自分の投稿」は削除し、すべて・画像・文章・作品集を左メニューに配置。幅800px以下では4項目を横並びにする。
- `/admin` は管理画面。下書き・投稿・調査と設計・ソース保存・投稿バックアップ・旧試作データ書出を集約。
- 閲覧用JavaScriptは保存済み試作データのAPIを呼ばず、公開見本だけを表示する。管理画面からの保存は外部公開を意味しない。本格的な公開機能は未実装。
- 管理画面・管理スクリプト・設計資料・ソースZIP・全APIをサーバー側で管理者認証する。Sitesの認証済みIDとメールを確認し、環境変数 `CHRONICLE_ADMIN_EMAIL` と一致する本人だけを許可。未ログイン401、他の利用者403、管理者設定欠落503。秘密情報の値をGitHubに置かない。
- Sites全体の閲覧範囲は本人専用のまま。一般公開への切替や既存WordPressの変更は行わない。
- Xserver移転時には独立認証を実装する。外部から任意指定された認証ヘッダーを信用しない。
