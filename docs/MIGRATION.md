# 本番移行の進捗

2026-11-15。UI比較を終え、既存サイトを動かしながら本番移行を準備している。

## 実環境で確認したこと

- エックスサーバーのスタンダードプラン。現在の対象ドメインはPHP 7.4.33、DBはMySQL 5.7。
- サーバーパネルにPHP 8.3.36（推奨）、8.4、8.5の選択肢がある。現行WordPressのPHPは変更していない。
- 公開ルート直下にWordPressがあり、アップロード画像に加えダウンロード配布用ディレクトリもある。
- 稼働中の設定ファイルからテーブル接頭辞を確認し、DB書出しの対象と一致を確認。接続秘密情報はソース管理へ保存しない。
- 公開記事189件＋固定ページ3件の192URLは既存の公開サイトマップ台帳と全件一致。その他の台帳項目はトップとカテゴリー。
- 下書き・非公開・改訂を含むため、DB全体を公開用JSONへ流用しない。非公開の抽出領域で元の状態を保持する。
- 添付ファイルの登録と相対パスのメタ情報を抽出できた。登録だけではファイル実体の完全性を保証しない。

## 保全状況

- 現時点のDBをgzで取得。圧縮展開検証成功。原本を本人の非公開ファイルとして保管し、公開ディレクトリ外の退避先にもアップロードした。
- ファイルマネージャによる公開ディレクトリの一括コピーは失敗。途中のコピーを `public_html-INCOMPLETE` と明示し、完全な退避として扱わない。元サイトは変更していない。
- 対象ドメインのWeb領域とWeb用設定だけをサーバー標準の自動バックアップから取得申請。取得済みデータの保存先は24時間で自動削除されるため、完了後の期限外保管が必要。完了・実体照合前に切替不可。
- WordPress管理画面は現在のクラウドブラウザーから接続制限。制限は解除していない。サーバーパネルとファイルマネージャは利用できている。

## 実装した移行補助処理

`scripts/inspect-wordpress-dump.py` はSQLを実行せず、指定テーブル接頭辞の投稿・メタデータ・分類・コメントを非公開SQLiteに抽出する。利用者と認証テーブルは抽出しない。optionsはURLや時差等の許可項目のみ。元DBは別途完全保全する。未知のSQL形式は停止し、出力先の上書きを拒否。UTF-8として読めない値を置換せずBLOBとして保持。抽出結果は公開サイトに接続しない。

```sh
python3 scripts/inspect-wordpress-dump.py /private/backup.sql.gz --prefix VERIFIED_PREFIX --output /private/staging.sqlite
python3 scripts/audit-wordpress-routes.py /private/staging.sqlite --prefix VERIFIED_PREFIX --inventory docs/public-url-inventory.json > /private/routes.json
python3 -m unittest discover -s tests -p 'test_wordpress_dump.py'
```

`VERIFIED_PREFIX` は実際の設定ファイルで確認した値に置き換える。秘密情報・実データ・サーバーアカウント名・バックアップURLをGitHubに置かない。実環境の非公開チェックポイントに保存する。

## 次の実作業

1. ファイルバックアップの完了確認と期限外への退避。画像・配布ファイルの存在、サイズ、ハッシュを照合する。切替直前に変更分と最新DBを再取得する。
2. 現在のUIを使うPHPの本番バックエンドを既存公開領域と分離して用意する。現行Worker/R2・Sites認証はそのままXserverでは動かない。独立認証とSQL保存を実装する。
3. 旧本文HTMLを欠損させず保全し、公開時の安全な変換・ショートコード・画像・ダウンロードリンク・内部リンクを照合する。旧HTMLを無検証で新サイトへ差し込まない。
4. 公開状態・URL・日時・広告設定を照合。一般コメント受付を実装するまでは、新規受付を既存機能相当と偽らない。
5. 復旧手順と実際の切替対象ファイルを用意してから本番切替を確認する。DNS変更は必要性がない限り行わない。旧WordPressとDBは即削除しない。

公開サイトに実データを移したとは扱わない。本番公開後の細かな表示改善は継続し、作品集等の全機能完成を切替の前提にしない。
