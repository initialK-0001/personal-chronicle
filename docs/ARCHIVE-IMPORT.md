# 個人アーカイブ取り込み

2026-11-16 ユーザーが索引内の既公開SNS等の記録を一括公開するよう明示指示。従来の一件ずつの下書き確認は今回の対象には適用しない。明示的な非公開・下書きは除外する。

索引20,883件。既存WordPress385件（公開189・非公開140・下書き56）を照合・除外し、X13,470・はてな6,630・mixi73・Seesaa37・アメブロ288の計20,498件を対象とする。画像実体は入力にないため元URL参照。ローカル検証で画像付き5,741件。画像の独立保全は未実施。

## 実装
- ArchiveImportは管理者のCLI専用。HTTP公開APIから起動不可。出典キーのSHA-256から既存WPと分離したID・URLを生成。衝突は中止し、既存キーは再取り込みでも上書きしない。
- 本文・題名・日時・出典リンク・分類・画像参照だけを移す。rawの評価数・位置メタ情報などを公開しない。初出投稿日を保持。
- 非公開/下書き除外、HTML無害化、一括トランザクション。実原本JSONはGitHubに置かない。
- 通常の旧記事と同じ編集・非公開化・バックアップ対象。編集公開後は取り込み時のプレビューを使わず最新内容から生成。
- 公開一覧50件、管理一覧100件ずつ追加表示。検索は読み込んだ全記録を対象。公開APIは現時点で全件を返すため応答サイズ約11MB。サーバー側ページングは未実装。
- 一覧での毎回のHTML無害化と管理側の一件ずつのSQLを避けた。個別ページはパスを指定したSQLで対象を取得。

## 配備と復旧
配備スクリプトは既存コードのハッシュを検査し private/archive-import-before-20261116 へ変更前コード・imports・editsを退避。別途渡したmanifestと10個の圧縮データ片を照合し、全WordPress IDが既存にある場合だけ追加。処理済みレポートと排他ロックで再実行を抑止。
取り込み前の既存行を変更しない。問題時はarchive_keyのある追加記事を非公開にするか、退避データと照合し専用復旧を行う。自動削除はしない。

## 検証
合成データ：一括公開・元日時・重複防止・非公開/下書き除外・不正HTML・編集後のプレビュー更新・非公開化・途中失敗のロールバック。既存legacy/legacy-editor/web/backup試験とtimeline3件成功。
実索引：ローカルで全20,498件の取り込み成功。本番起動用PHPはローカルの追加拡張設定を継承しないため子プロセス起動検証は専用PHPラッパーで再確認。
20,687件（WP公開を含む）の一覧生成約0.6秒、SSR50件約30KB、128MB制限でピーク約106MiB。実サーバーの応答と配備結果はVERIFICATION.mdへ追記。
