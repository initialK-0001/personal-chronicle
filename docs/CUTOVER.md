## 本番操作の順序

1. コードと移行処理を準備し、独立した検証環境で上記の残項目を確認する。現行サイトを検証のために停止しない。
2. 一度の接続中に、新サイト本体・秘密設定・専用DB・非公開画像保存先を準備し、実ホストで検証する。配置可能なPHP実行環境とDB接続手段は実環境で確認する。未確認のSSH利用可否を前提にしない。
3. 現行WordPressの最新DB・全ファイルを保全し、前回バックアップとの差分を取り込む。既存バックアップの削除はしない。旧uploadsと配布ファイルを新サイトから参照できる非公開領域へ配置する。
4. 実際に変更するファイル・PHP設定と、変更前へ戻す手順を確定して利用者へ提示する。切替承認はその時点で受ける。
5. 承認後、入口とPHP設定を切り替え、公開URL・画像・配布・管理操作・広告を確認する。DNS変更が必要かは実配置次第であり、現時点では変更しない。
6. 異常時は用意した入口・設定へ戻す。新サイトで受け付けたデータは退避し、旧バックアップで上書きしない。WordPressの削除は移行・検証後の別判断とする。

本書は切替完了報告ではなく作業台帳。新サイトのバックアップはWordPressのバックアップの代用ではない。実装範囲の詳細と再現コマンドはXSERVER.mdとVERIFICATION.mdに記録する。
